# 百慕：从分镜到成片

百慕是人和 Codex 共用的本地剪辑器。GPT 帮你整理分镜和制作要求，Codex 读取电脑上的素材，通过百慕接口完成剪辑。审核后先汇报人工，人工调整意见，再由 Codex 返修。

## 一个入口

分享本仓库首页即可，下载、技能安装和 SOP 都从这里开始。

[下载百慕完整包](https://github.com/kuro19711/baimu/releases/latest/download/baimu-windows-x64.zip)

下载完整包后解压，运行“安装百慕.exe”，然后启动百慕。0.6.3 包含软件、运行环境、语音识别模型、两份外置技能与本 SOP，一次下载即可开始。技能位于解压目录的 skills 文件夹，可让 Codex 从这里安装。

本仓库 `skills/` 保存最新外置技能，`builtin-skills/` 保存审核标准与修改方法。给 Codex 下面这句话，让它完成安装，不必再找技能下载地址：

> 从 https://github.com/kuro19711/baimu 安装 skills/baimu 和 skills/short-drama-review。检查已有同名技能并更新原位置，读取 baimu 技能，通过本机接口检查百慕状态。

手动安装时，复制两个完整文件夹到用户或项目的 `.agents/skills`。已在 `.codex/skills` 被当前客户端识别的技能更新原位置，避免重复安装。技能未出现时重新打开 Codex。[官方技能说明](https://learn.chatgpt.com/docs/build-skills)。

软件与外置技能每天首次使用时检查 GitHub 最新正式版，同一天的不同对话和窗口共用检查结果。有新版时提醒一次；在“更多 → 设置 → 关于与更新”可立即重查、查看发布说明和下载。检查失败不影响制作。

## 让 GPT 带着你做

把本页链接发给 GPT，再说：

> 请读完整个页面，作为我的百慕制作助手。按“安装接入 → 准备资料 → 分镜映射 → 制作 → 审核 → 人工意见 → 返修交付”带我完成。先判断我在哪一步，每次给当前步骤的操作和一段可复制给 Codex 的指令。已有资料直接用，缺少的关键资料集中问。

GPT 无法打开链接时，把本页正文粘贴给它。网页聊天中的分镜不会自动进入电脑上的 Codex 会话，需要保存或附上文件。

## 1. 前置准备

把剧本、分镜、纯净稿、抽卡视频和旁白录音放入一个剧目文件夹，给出音乐库位置。视频、录音建议按集整理，名称可以沿用现有习惯。

```text
剧名/
  剧本与分镜/
  视频/EP01/…
  录音/EP01/…
  工作资料/
  【剧名】卡后导出视频/
```

纯净稿保留实际发声正文，把角色名、镜号、动作说明与发声文字分开。说明目标语言、制作集数、字幕样式、音乐库及输出目录。文件名用于定位，集数仍按实际内容核对。

## 2. 让 Codex 读到分镜

在 GPT 中完成分镜后，保存为 Markdown、TXT、表格或 Word，放入项目目录。给 Codex 绝对路径，或把文件附到它的会话里。图片/PDF 分镜先识别并核对镜号、对白和旁白。

分镜建议包含下面这些信息，已有分镜不必重做格式：

| 集数 | 镜号 | 画面与动作 | 人物对白 | 旁白 | 对应素材 |
|---|---|---|---|---|---|
| EP01 | S01 | 女主转身看向门口 | Who are you? | 留空 | EP01_S01_take2.mp4 |

给 Codex：

> 项目根目录是【路径】，分镜在【路径】，纯净稿在【路径】。先读取文件，列出集数、镜号、对白/旁白与素材的对应关系，标出缺素材、错集录音和未能匹配的镜头，再按制作要求继续。

这一步核实 Codex 读到的是分镜内容，而不只是文件名。

## 3. 提制作要求

把模板中的括号换成实际信息：

> 使用本机九州百慕制作【剧名】【集数】。项目根目录【路径】，分镜【路径】，纯净稿【路径】，视频【路径】，录音【路径】，音乐库【路径】，目标字幕语言【语言】。先核对资料和软件状态，简要说明思路，然后完成可处理的集数，最后统一汇报问题。
>
> 根据分镜和剧本拼接已有视频，让旁白对应画面。录音若包含整集串读，核对后只留旁白；保留视频人物对白和必要环境声。旁白与无人声画面时长不匹配时，先尝试 10% 以内变速；仍不匹配时可删不影响剧情转折的旁白。错集或缺音频保留待补工程，继续其他集。
>
> 画幅 1080×1920，帧率按源素材实测。使用百慕预设效果字幕。文字以纯净稿校对，时间以最终人声逐词对齐。去分句标点，保留缩写、词内连字符/撇号和数字有效标点；回答句 No. 显示为 No。西语、葡语保留问号和感叹号。按说话气口分句，默认框宽下超过两行时合理拆分，不让最后一个词单独成条。人物实际说中文时保留原声，字幕按目标语言处理并报告时间。
>
> 按剧情情绪选音乐，BGM 基础音量约 −11 dB，全集保持统一，不得压过旁白和对白。画面、声音位置或速度变化后重查字幕同步。用实际导出 MP4 检查声音、字幕、重复/冻结画面及打码，未完成检查如实报告。
>
> 成片放【项目根目录】/【剧名】卡后导出视频，命名 1.mp4、2.mp4……目录只放各集 MP4。工程、字幕、报告放“工作资料”，保留一套。完成后告诉我视频目录、完成集数及需我处理的问题。常规操作直接执行，缺关键资料或需要剧情取舍时集中询问。

## 4. 提审核要求

制作完成后单独发：

> 审核【剧名】【集数】实际成片，按百慕当前内置标准全项检查。完成后先汇报“集数、时间、问题、确认程度”，附修改建议，未检查项单独标明。等我调整清单后再修改。本次补充要求：【没有可留空】。

审核涵盖裸露、未成年人伤害、成人流血/自伤、禁用场景、字幕、声音与音乐、品牌标识和画面技术质量；普通服装光线穿帮不查。字幕查可能侵权的名词，正常人名不会仅因属于专名被替换。Logo 重点看车头车尾、轮毂、手机和电脑背面，证据不足保留待核。

详细规则在 `builtin-skills/review/SKILL.md`，修改方法在 `builtin-skills/repair/SKILL.md`。有内置规则接口时使用软件保存的当前版本；旧版使用随包基线并说明版本。

新版审核栏显示“无问题 / 有问题 / 待复核 / 未检查”，有问题置顶。修改栏可取消勾选、编辑并保存最终意见。旧版在聊天中显示同样的问题单，人工直接回复保留项和修改方法。

## 5. 人工意见后返修

看完报告后可以直接说：

> 第 2 项保留。第 1 项只替换字幕品牌词，保持时间。第 3 项统一降低本集 BGM，确保旁白和对白清楚。其余按清单建议修改，导出新 MP4 复审。

新版保存意见后点击“按清单修改”，把生成的任务交给 Codex。Codex 读取固定清单中的最终意见。人工意见已经给出后，常规修改直接完成，不逐项再问。复审检查原问题及受影响音画，汇报已解决、未解决和需要人处理的项目。

## 给读取本页的 GPT / Codex

先识别使用者当前阶段，给当下可执行的步骤。GPT 负责解释、整理分镜与生成任务提示；有本机文件和工具权限的 Codex 负责读取素材和调用百慕。沿用已给资料与决定。审核后有一次人工审阅，人工意见之后继续执行。完成情况以实际文件、接口回读及成片检查为依据。

源码包和第三方许可保留在仓库及发布页。0.6.1 新增审核与修改双栏，旧版用户安装更新后使用。
