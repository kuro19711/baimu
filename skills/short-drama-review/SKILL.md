# 短剧审核与返修

流程：审核成片 → 汇报人工 → 人工选择问题、编辑修改意见 → 按最终清单返修 → 新成片复审。

## 读取标准

百慕工程使用相邻的 [baimu 技能](../baimu/SKILL.md)，读取 review-context 和 review-workflow。以软件里当前保存的审核标准、返工方法和本集范围为准。默认全项检查，人工明确排除项按其选择。

打开或接入百慕前，按 baimu 技能检查 GitHub 最新发布；同一次打开流程已检查过就直接继续。

纯视频或旧版软件未提供规则接口时，读取 [references/rules.md](references/rules.md) 与 [references/repair.md](references/repair.md) 的随包基线，并说明使用了哪个版本。用户本次要求优先，只有影响结果的歧义集中询问。

## 审核与汇报

检查真实视频、声音与字幕，记录成片版本和时间。ASR、OCR、工程数据用于发现候选，结合实际画面与试听下结论；未覆盖部分标为未检查。

按“集数、时间、问题、确认程度”简表汇报，证据另存。所有适用类别都保留；服装、光线等普通穿帮不查。可能侵权的名词按实际所指与语境判断，正常人名不会因属于专名被禁用。标识区分疑似、品牌已确认、已确认需处理。

有工作流接口时，将各项 checks 和具体 findings 写回软件：审核栏展示无问题、有问题、待复核、未检查，修改栏展示建议方法。完成审核后交给人工选择和调整，先停在报告。

## 返修与复审

人工给出“按清单修改”后直接执行最终意见，常规步骤不逐项确认。有固定批次时读取 active_batch.findings[].plan；纯视频报告则使用人工回复后的最终清单。保留人工取消项。

通过百慕接口差量编辑并回读，遵守版本与轨道锁；按修改中、待复审、已解决/未解决回写。实际新 MP4 检查原问题及受影响的字幕、音频、音乐、打码和切点。新发现的问题另行汇报人工。
